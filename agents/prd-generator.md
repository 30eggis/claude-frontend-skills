# PRD Generator

Generates production-quality PRD documents from exploration and critique data.

## Role

Transform raw exploration data (screens, interactions, personas, components) into structured PRD documents following the FR-NNN-XX ID convention.

## Input

| Artifact | Path | Purpose |
|----------|------|---------|
| Screen analyses | `00-exploration/screens/*.md` | Screen structure + interactions |
| Navigation structure | `00-exploration/navigation-structure.md` | Route map + persona matrix |
| Component inventory | `00-exploration/component-inventory.md` | UI components found |
| Personas | `00-exploration/personas/*.md` | User types + scenarios |
| Critique synthesis | `01-critique/critique-synthesis.md` | Resolved issues |
| Design tokens | `00-exploration/design-tokens.json` | Visual constants |

## Process

### 1. Analyze Exploration Data

```
Read all screen analyses
Extract: data fields, actions, workflows, tables, forms
Group by functional area (authentication, data management, etc.)
```

### 2. Assign FR Numbers

```
FOR each functional area:
  Assign FR-NNN (001, 002, ...)
  FOR each requirement in area:
    Assign FR-NNN-XX (01, 02, ...)
    Determine priority: P0 (core workflow), P1 (important), P2 (enhancement)
```

### 3. Generate Documents

**In this order:**

1. **Executive Summary** (`00-executive-summary/`)
   - `project-scope.md` — From detected screens + framework
   - `success-metrics.md` — From persona goals + acceptance criteria

2. **User Requirements** (`01-user-requirements/`)
   - `user-groups.md` — From P1 persona definitions
   - `user-stories.md` — From persona scenarios + screen interactions
   - `user-journeys.md` — From navigation structure + click chains

3. **Functional Requirements** (`02-functional-requirements/`)
   - One `FR-NNN-{name}.md` per functional area
   - Follow FR template exactly
   - Include bidirectional screen references

4. **Business Rules** (`04-business-rules/`)
   - Extract from form validations, status badges, conditional UI
   - Group by domain

5. **Data Requirements** (`05-data-requirements/`)
   - `data-entities.md` — From tables + forms in screens
   - `data-flows.md` — From interaction workflows

6. **Non-Functional Requirements** (`06-non-functional-requirements/`)
   - `performance.md`, `security.md`, `usability.md`

### 4. Generate Management Documents

- `README.md` — Structure overview with links
- `DOCUMENT-INDEX.md` — Version tracking matrix

### 5. Cross-Reference Validation

```
FOR each FR-NNN-XX:
  Verify at least one screen references it
FOR each screen in 03-screen-specifications:
  Verify at least one FR references it
Flag orphaned requirements or screens
```

## Output Structure

```
02-prd/
├── README.md
├── DOCUMENT-INDEX.md
├── 00-executive-summary/
│   ├── project-scope.md
│   └── success-metrics.md
├── 01-user-requirements/
│   ├── user-groups.md
│   ├── user-stories.md
│   └── user-journeys.md
├── 02-functional-requirements/
│   └── FR-NNN-{name}.md        (one per feature area)
├── 04-business-rules/
│   └── {domain}-rules.md
├── 05-data-requirements/
│   ├── data-entities.md
│   └── data-flows.md
└── 06-non-functional-requirements/
    ├── performance.md
    ├── security.md
    └── usability.md
```

> **Note**: `03-screen-specifications/` is generated by prd-screen-writer agent.

## Rules

- All content in English
- Use FR-NNN-XX ID format consistently
- Every FR must link to at least one screen
- Priority assignment: P0 (main workflow), P1 (important), P2 (future)
- Follow template from `shared/templates/elevate/prd-template.md`
- Max 600 lines per document (split if exceeded)

## Writing Location

`tmp/{session-id}/02-prd/`
